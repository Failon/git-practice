# Kaggle Playground S6E10 — Predicting Airline Satisfaction

Задача: предсказать вероятность `satisfaction` (satisfied / neutral or dissatisfied).
Метрика: ROC AUC. Данные соревнования — синтетика, сгенерированная из оригинального датасета
Airline Passenger Satisfaction (~130k строк).

Особенности данных соревнования (train 699 635, test 299 844):
- 13 рейтингов: колонки `Inflight service` из оригинала нет; таргет — True/False, доля 0.444.
- Задержки почти всегда нулевые (среднее около 1 мин против примерно 15 в оригинале); 292 пропуска в `Arrival Delay`.
- Точных совпадений строк с оригиналом — 17, дубликатов в train нет.

## Идеи (план экспериментов)

| # | Идея | Зачем |
|---|------|-------|
| 1 | Логистическая регрессия, все рейтинги one-hot | линейный бейзлайн, полезен в бленде |
| 2 | MLP на one-hot | другая индуктивная предвзятость, диверсификация бленда |
| 3 | HistGradientBoosting (sklearn) | быстрый GBDT-бейзлайн без зависимостей |
| 4 | LightGBM на сырых признаках | основная рабочая лошадка |
| 5 | LightGBM + ручные фичи (агрегаты рейтингов, задержки) | проверить, дают ли FE что-то деревьям |
| 6 | XGBoost | второй GBDT для бленда |
| 7 | CatBoost, рейтинги как категории | на Playground обычно силён |
| 8 | Добавить оригинальный датасет к train | классический трюк Playground |
| 9 | Target/count-encoding комбинаций рейтингов | синтетика ломает связи, частоты помогают |
| 10 | Бленд / стэкинг OOF (rank-average, логрег по OOF, hill climbing) | финальный прирост |
| 11 | Тюнинг Optuna лучших моделей, мульти-сид | вылизывание |

## Результаты MVP (прокси: оригинальный датасет, 130k строк, 5-fold)

`clean` — оригинальные данные; `noisy` — 8% перевёрнутых меток + ±1 к 8% рейтингов
(синтетика Kaggle заметно шумнее оригинала: лучшие публичные результаты ≈0.958, а на оригинале ≈0.996).

| модель | clean AUC | noisy AUC | время (clean) |
|---|---|---|---|
| CatBoost (рейтинги как категории) | **0.99571** | 0.90988 | 688s |
| LightGBM | 0.99566 | **0.91052** | 25s |
| LightGBM + FE | 0.99557 | 0.91025 | 33s |
| HistGB | 0.99553 | 0.90951 | 14s |
| XGBoost | 0.99547 | 0.90977 | 30s |
| MLP | 0.99431 | 0.90726 | 73s |
| LogReg one-hot | 0.97942 | 0.89505 | 4s |
| rank-blend всех (равные веса) | 0.99525 | 0.91010 | — |

Выводы:
- GBDT заметно лучше линейной модели и MLP; между собой бустинги в пределах ~0.0002–0.0007.
- Ручные агрегаты рейтингов деревьям не помогают (деревья сами их находят).
- Слепой равновесный бленд со слабыми моделями хуже лучшей одиночной → нужен
  бленд с подбором весов по OOF / hill climbing.
- CatBoost в 25 раз медленнее; на 700k строк его надо запускать на GPU или с меньшим числом итераций.
- Ранжирование на прокси — ориентир; проверять на настоящем train.csv.

## Доводка 1: частоты и кодирование значений

Абляция частотного кодирования (`src/exp.py cnt_*`), LightGBM, база 0.95896:

| набор частот | AUC |
|---|---|
| только числовые (Age, Distance, 2 задержки) | **0.95965** |
| одиночные: рейтинги + числовые | 0.95954 |
| числовые + числовые×категории | 0.95950 |
| одиночные + весь вектор рейтингов | 0.95950 |
| одиночные + пары + вектор рейтингов | 0.95931 |
| одиночные + пары (v1) | 0.95925 |
| только рейтинги | 0.95890 |

Вывод: весь сигнал в частоте значений числовых колонок, пары рейтингов — шум.
Редкие значения `Flight Distance` → 68.5% довольных против 33–46% у частых
(артефакт генератора синтетики). Все значения числовых колонок есть в оригинальном датасете.

Развитие идеи:

| эксперимент | AUC |
|---|---|
| частоты числовых + target encoding значений числовых (в фолдах) — `numte` | 0.96022 |
| частоты числовых + статистики по значению из оригинала (count, доля satisfied) — `origstat` | 0.96012 |
| оба — `combo` | 0.96024 |
| + TE Age/Distance × категории — `numte2` | **0.96027** |

Бленд (hill climbing): numte2 0.4, origstat 0.2, numte 0.2, cnt_rowkey 0.2 → **OOF 0.96067**
→ `submissions/sub_v2_blend.csv` (v1 был 0.95948).
